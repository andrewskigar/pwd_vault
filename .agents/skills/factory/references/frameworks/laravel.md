# Laravel Overlay

Loaded on top of `php.md` when the component requires `laravel/framework`. Laravel idioms beat the generic PHP pack where they conflict. Match the app's existing structure (actions, services, form requests, policies) before introducing a new pattern.

## Where the generic rules bend

- **Eloquent models** extend `Model`, are not `final` or `readonly`, and use framework conventions (`$fillable` or `$guarded`, `casts()`, relationships, scopes). Keep business rules out of fat models when the app already uses actions or services. Never set `$guarded = []` on models filled from request input.
- **Facades and helpers** (`Cache::`, `now()`, `config()`) are fine in controllers, jobs and wiring code if the app uses them. In domain/action classes, prefer constructor injection of the contract (`Illuminate\Contracts\Cache\Repository`, a `Clock` interface) so tests don't need facade fakes.
- **Controllers, jobs, listeners, form requests, policies** extend or implement framework base types as generated by `artisan make:*`. `final` is fine on your own controllers and actions.
- Laravel's fluent builders (query builder, `Http::`, collections) are framework APIs, not the "no fluent business methods" smell.

## Boundaries

- Validate input in **Form Requests** (or `$request->validate`) and authorise with **policies/gates** (`$this->authorize`, `can` middleware). Pass validated data (`$request->validated()`, a DTO) inward, never the whole `Request`.
- Use backed enums with `casts()` for state columns, and route-model binding for IDs.
- Migrations must be reversible (`down()`) unless the repo says otherwise. Never edit a migration that has already shipped; add a new one.

## Tests

- Run tests through the repo's runner (`php artisan test`, `vendor/bin/pest`, `vendor/bin/phpunit`).
- Test at the HTTP seam with feature tests (`$this->postJson(...)->assertCreated()`), using `RefreshDatabase` and factories. Use unit tests for pure domain/action classes.
- Use `Http::fake()`, `Queue::fake()`, `Mail::fake()`, `Event::fake()` at boundaries, and assert observable outcomes (responses, database rows via `assertDatabaseHas`, dispatched jobs).
- Static analysis is usually Larastan (`phpstan.neon` with the Larastan extension). Respect its configured level.
